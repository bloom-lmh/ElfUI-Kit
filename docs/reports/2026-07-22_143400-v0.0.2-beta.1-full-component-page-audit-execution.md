## 目录跳转修复

根因位于 Playground 的标题提升机制：紧邻 Playground 的 H2 会被隐藏，并把文字提升为卡片标题；DocsToc 之前仍把隐藏 H2 注册为滚动目标，因此目录项存在，但点击后视觉上不会移动到案例卡片。

本轮统一改为：

1. 被提升的 H2 不再持有 `data-docs-toc-id`。
2. 目录 ID、IntersectionObserver 和滚动定位统一绑定到可见的 `elf-playground`。
3. API、Props、Events、Expose、Methods、Slots 及中英文别名继续统一折叠成一个 API 目录项。
4. 新增回归测试，明确断言隐藏 H2 不会被滚动，实际 Playground 才是导航目标。

真实浏览器随后覆盖 92 个路由和 673 个目录项，结果为 0 失败。

## Script 覆盖结果

原先只统计 `script` 属性会误判“有脚本就是完整”。本轮审计增加了模板依赖分析：从事件、双向绑定、循环、条件、动态属性和插值中提取状态与处理函数，再确认 Script 中是否存在对应定义。

| 指标                       | 修复前 | 修复后 |
| -------------------------- | -----: | -----: |
| 带 Script 的 Playground    |    196 |    254 |
| 完全缺失且确实需要 Script  |     66 |      0 |
| 已有 Script 但缺少模板依赖 |     41 |      0 |
| 无 Script 的纯静态案例     |    186 |    128 |

补充原则：

- 数据、状态、事件处理函数和受控值必须进入 Script。
- 纯外观、静态布尔属性、静态数值和纯插槽案例不添加空壳 Script。
- Script 展示实际可复制的 `useRef`、数组、映射函数、事件读取和状态更新逻辑。
- Provider、日期时间、表格、树、穿梭框、浮层等复合案例补齐了上下游依赖，不只展示一个孤立变量。

## 仍需新增的案例

当前案例数量已经较多，下一阶段应补边界、组合与无障碍，不应继续堆纯颜色/尺寸案例。全部组件的逐页建议见关联的《组件案例审计报告》，以下是最高优先级：

| 领域       | 组件                                          | 必补案例                                                                                    |
| ---------- | --------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 浮层与焦点 | Dialog、Drawer、Tooltip、PopConfirm、Tour     | 焦点陷阱与返回、Esc、外部点击、嵌套浮层、滚动锁、层级、销毁恢复焦点                         |
| 表单契约   | Form、FormItem                                | 同步/异步校验、validate/reset/clearValidate、滚动首错、原生 submit、动态字段、Provider 继承 |
| 选择输入   | Select、Autocomplete、Cascader                | 完整键盘路径、远程加载/空/错误、超长选项、虚拟化、浮层碰撞与滚动跟随                        |
| 日期时间   | DatePicker、TimePicker、Calendar、ColorPicker | 禁用边界、键盘、格式/value-format、范围重选、清空、外部关闭、窄屏、国际化                   |
| 大数据     | Table、Tree、Transfer、VirtualList            | 1k+ 数据、虚拟滚动、固定头列、键盘焦点、筛选定位、动态高度、长标签、加载/空状态             |

特别短缺的页面：List、Tour、ColorPicker、Dialog、Drawer、Select、VirtualList、Masonry、PageHeader。案例过多需要合并的页面：Table、Tabs、Button、Input、Alert、Switch、Skeleton。

## 分类合理性建议

组件源码目录暂时不要大搬迁。现有分类不会阻碍使用，贸然移动会影响导出路径、测试和文档路由；更适合先优化文档导航的展示分组。

### 建议保留

- Layout、Basic、Navigation、Picker、Providers 的边界清楚。
- Picker 独立于 Form 是合理的，日期、时间、颜色和日历已经形成完整领域。
- Container、Space 保留兼容路由，但不再作为一级菜单中的独立推荐组件；Grid、Flex 是推荐入口。
- Utilities 是样式能力，不应混入组件源码分类。

### 建议调整文档导航，不调整源码路径

1. Form 有 17 页，单组过长。导航上拆成“输入 Input”“选择 Selection”“表单 Form”，路由仍保持 `/form/*`。
2. Data 有 20 页，拆成“数据展示”和“数据集合”：Table、List、VirtualList、Tree、Transfer、InfiniteScroll 放入数据集合，其余保留数据展示。
3. Feedback 建议拆出“Overlay 浮层”：Dialog、Drawer、Tooltip、PopConfirm、Tour；Alert、Loading、Message、Notification 留在 Feedback。
4. “样式和动画”当前只有 Utilities，建议改名为“Styles & Utilities 样式工具”，并放在组件分类之后。
5. Providers 菜单命名统一为单数双语：`DefaultsProvider 默认配置`、`LocaleProvider 国际化`、`ThemeProvider 主题`。

这样能缩短菜单扫描距离，又不增加多级页面、不改变现有 URL，也不会造成组件导出破坏。
