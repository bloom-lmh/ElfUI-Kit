# ElfUI Kit 组件案例审计报告

- 日期：2026-07-22
- 版本：0.0.2-beta.1
- 范围：`src/pages` 下 77 个公开页面（另含内部 Debug 页）、392 个 Playground、现有组件 `plan.md` 与页面级测试
- 对标：Vuetify 当前组件目录、Vuetify0 的 Breadcrumb / Input / Data Table 交互契约，以及 ElfUI 既有 Element Plus 对齐计划

## 结论

案例数量已经足够多，当前主要问题不是“案例少”，而是案例层级、边界状态和测试分布不均：

1. 页面 H1 应保留，作为页面唯一主标题。
2. 紧邻 Playground 的案例 H2 属于重复视觉层级，应提升为卡片标题；API、内容章节和示例内部语义标题继续保留。
3. 标题应描述用户能观察到的行为，避免只写属性名，也避免“基础用法案例”一类冗余后缀。
4. 优先补交互边界、键盘/焦点、加载/空/错误、移动端和大数据；不建议继续堆叠仅颜色或尺寸不同的静态案例。
5. 页面级回归测试明显偏科：Basic、Feedback、Form、Providers 目前没有页面级测试。组件单测不能完全替代真实页面中的 Provider、Popover、路由和 Shadow DOM 组合验证。

## 已统一的案例标题规则

- 保留每页 `<h1>` 与页面说明。
- Playground 自动识别紧邻自己的 `<h2>`，隐藏重复 H2，并将其文字用于卡片标题。
- 不处理 API 前的 H2，也不处理 Playground 内容内部的 H2/H3。
- 标题字号提升一级；“基础用法/基本用法”精简为“基础”，“案例”后缀移除，`/`、`+`、`＆` 统一为中点分隔。
- 状态、计数与命令按钮统一放到 `slot="status"`，不再占用 demo 内容高度。

## P0：下一批必须补齐

| 领域 | 组件 | 必补案例 |
| --- | --- | --- |
| 浮层与焦点 | Dialog、Drawer、Tooltip、PopConfirm、Tour | 焦点陷阱与返回、Esc、点击外部、嵌套浮层、滚动锁、z-index 堆叠、销毁后恢复焦点 |
| 表单 | Form、FormItem | 同步/异步校验、validate/reset/clearValidate、滚动到首错、原生 submit、动态字段、Provider 尺寸与禁用继承 |
| 选择输入 | Select、Autocomplete、Cascader | 键盘完整路径、远程加载/空/错误、超长选项、大数据虚拟化、teleport 碰撞与滚动跟随、表单校验 |
| 日期时间 | DatePicker、TimePicker、Calendar、ColorPicker | 禁用边界、键盘、格式化与 value-format、范围重选、清空、外部关闭、移动窄屏、国际化 |
| 大数据 | Table、Tree、Transfer、VirtualList | 1k+ 数据、虚拟滚动、固定头/列、键盘焦点、筛选后定位、动态行高/长标签、加载与空状态 |
| Provider | Locale、Theme、Defaults | 嵌套覆盖优先级、运行时切换、组件默认值继承、服务组件继承、暗色与英文组合 |

Vuetify 的案例组织更强调“真实边界”：Breadcrumb 会展示响应式折叠、路由派生、当前页 `aria-current` 和可替换省略项；Input 把校验、表单注册和原生输入类型放在同一契约中；Data Table 将虚拟滚动、粘性表头和排序组合验证。ElfUI 后续案例也应优先采用这种组合验证，而不是把每个 prop 拆成孤立卡片。

### Utilities（1 页 / 1 个综合 Playground）

综合 Playground 的方向正确，但 13 类工具全部塞在一个页面会增加视觉回归难度。保留单页目录，按 Borders、Display、Flex、Spacing、Typography 等分区；每个主题使用不同的真实场景，不再复用同一张“配置卡”。必须补打印媒体说明、响应式前缀冲突、组合优先级和暗色对比。

## 重复案例清理清单

1. Button、Tag、Alert、Switch：颜色/变体/尺寸合并为可比较的矩阵，不再一项一个 Playground。
2. Skeleton：文字、圆形、矩形、图片合并为“形状”；保留卡片、列表、Dashboard 三个真实骨架。
3. Input：variant 与 density 合并成一个交互矩阵；各输入类页面只展示自身特有行为。
4. Layout：Container/Space 的基础能力与 Grid/Flex 重复，导航保持平铺，但文档明确“兼容组件”和“推荐组件”。
5. Empty 与 Result：Empty 负责无数据/无搜索结果，Result 负责流程结果/错误页，避免同一语义重复。
6. Loading、Message、Notification：共享 Provider/服务调用说明，组件页只保留各自特有交互。
7. Tabs、Menu、Table：现有案例很多，下一阶段只补边界和性能，不再添加纯静态样式案例。

## 测试缺口

- 页面级测试现状：Basic 0/7、Data 3/20、Feedback 0/9、Form 0/17、Layout 6/9、Navigation 4/8、Picker 1/4、Providers 0/3、Utilities 1/1。
- 每页不需要都有重型截图测试，但每个组件族至少需要一个真实页面集成测试。
- Popover 类组件必须在真实浏览器覆盖：点击外部关闭、滚动跟随、碰撞翻转、层级和焦点返回。
- Provider 类必须用“中文/英文 × 亮/暗 × defaults”组合跑页面冒烟。
- 大数据类必须记录渲染节点数量和滚动后焦点/选择状态，而不只断言 DOM 文本存在。
