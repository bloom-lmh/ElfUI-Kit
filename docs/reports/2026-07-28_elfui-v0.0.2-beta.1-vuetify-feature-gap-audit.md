# ElfUI × Vuetify 能力缺口与目录去重报告

日期：2026-07-28
版本：v0.0.2-beta.1

## 结论

ElfUI 并不缺少一整套 Vuetify Features 页面，真正缺少的是两类内容：

1. 跨组件质量契约：无障碍、构建入口与全局样式边界。
2. 少量尚未公共化的服务：程序化滚动、date adapter、platform/SSR 和类型安全的全局 alias。

ConfigProvider、ThemeProvider、IconProvider、LocaleProvider、Layout、Picker、Anchor、BackTop 与 Utilities 已经覆盖其余大部分能力。继续按 Vuetify 菜单逐项新增页面只会造成重复，因此本轮采用“一个能力、一个权威页面”。

## 去重后的能力映射

| Vuetify 概念 | ElfUI 权威入口 | 处理方式 |
| --- | --- | --- |
| Global configuration / Blueprints / Display | Global configuration | 合并，ConfigProvider 统一承载 |
| Theme / Material palette / Sass variables | Theme & customization | 合并，强调 runtime token 与构建期边界 |
| Icon fonts / Aliases / Sets | Icons | 复用现有 IconProvider 案例 |
| Internationalization / RTL | Internationalization | 复用 LocaleProvider |
| Accessibility / Hotkeys | Accessibility | 新增一页，区分组件契约与应用责任 |
| Entry points / Reset / CSS layers / Tree-shaking | Build & styles | 新增一页，只列真实 exports |
| Application layout | Layout | 不新增重复 Feature 页面 |
| Dates | Picker | 不新增重复 Feature 页面 |
| Programmatic scrolling | Anchor / BackTop | 不新增重复页面；公共服务列入 P1 |
| CSS utilities | Utilities | 保持一个独立一级页面 |

## 当前已经具备的能力

- ConfigProvider 可统一组合 defaults、blueprint、theme、locale、icons、display 与 motion。
- ThemeProvider 支持局部主题、命名主题、token 覆盖与继承。
- IconProvider 支持 aliases、sets 与默认 set。
- LocaleProvider 支持 locale、messages、fallback 与 RTL。
- Layout、Grid、Flex、Splitter、Scrollbar 和 Masonry 已有独立组件案例。
- DatePicker、TimePicker、Calendar 已在 Picker 分类中承载日期时间体验。
- Utilities 已覆盖边框、圆角、内容、显示、间距、排版等工具类。
- 包当前公开 `@elfui/kit` 与 `@elfui/kit/styles/utilities.css` 两个稳定入口。

## 真正缺失的功能

### P1：值得进入公共 API

| 能力 | 当前状态 | 建议 |
| --- | --- | --- |
| `goTo` service | Anchor、BackTop 各自滚动 | 提供 selector/element/container、offset、duration、easing 和取消能力 |
| Date adapter | 组件直接使用 Date | 定义 parse、format、compare、startOfWeek、locale 的适配协议 |
| Platform / SSR context | display 已覆盖断点 | 增加 SSR 初始 viewport、platform flags 与 hydration 测试 |
| Global aliases | `useComponents` 支持局部别名 | 在 ConfigProvider 增加类型安全 alias 映射后再写文档 |
| Stable component entries | package 只有主入口 | 先设计 exports、sideEffects 与产物测试，再承诺深层按需导入 |

### P2：生态增强

- 外部 i18n adapter。
- 品牌 preset 独立包与版本策略。
- token 类型、文档、设计工具同步生成。
- axe/ARIA 自动检查、键盘矩阵和截图回归。

## 不应新增的重复页面

- 不新增 Blueprints：属于 Global configuration 的一个案例。
- 不新增 Display & platform：断点配置留在 Global configuration，SSR 能力实现后再补同页案例。
- 不新增 Icon fonts：Icon 页面已经覆盖 set 与 alias。
- 不新增 Sass variables / Material palette：主题值由 Theme 页面负责。
- 不新增 Programmatic scrolling：使用场景属于 Anchor / BackTop。
- 不新增 Dates：属于 Picker。
- 不新增独立 Providers 一级组：Provider 是实现机制，不是用户寻找能力时的首要分类。

## 对 ElfUI 框架的建议

1. 保持 ConfigProvider 只做组合和下发，Defaults、Theme、Locale、Icons 各自维持小而稳定的上下文。
2. 公共 service 应具备取消、清理、SSR no-op 与类型约束，避免把跨组件行为复制进组件。
3. package exports 必须成为测试契约；文档不能展示未发布的深层导入。
4. Shadow DOM 内部样式、应用 reset、Utilities 和主题 token 要明确四层职责。
5. 能力成熟后再增加菜单项，规划中的 API 只放报告，不伪装成已支持功能。

Vuetify 官方安装文档公开区分主入口、样式、组件、directives、blueprints、locale adapters 与 iconsets，说明构建入口本身需要被当作稳定契约。[Vuetify installation and exposed exports](https://vuetifyjs.com/en/getting-started/installation/)

Vuetify 的升级文档也把 reset、CSS layers、主题与样式迁移分别说明；ElfUI 采用相同的职责划分，但用更少的权威页面表达。[Vuetify upgrade guide](https://vuetifyjs.com/getting-started/upgrade-guide/)

Vuetify 支持编译期 Sass variables 与 presets；ElfUI 当前以 runtime CSS token 为主，短期应清楚说明差异，不应声称已经具备同等构建期 API。[Vuetify Sass variables](https://v2.vuetifyjs.com/en/features/sass-variables/)，[Vuetify presets](https://v2.vuetifyjs.com/en/features/presets/)
