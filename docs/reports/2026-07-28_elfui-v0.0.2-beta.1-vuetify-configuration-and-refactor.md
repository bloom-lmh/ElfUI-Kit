# ElfUI 配置能力、代码收敛与框架评估

日期：2026-07-28  
版本：v0.0.2-beta.1

## 结论

ElfUI 已经具备 Custom Element、Shadow DOM、Provider 和 token 化主题的基础，适合把“组件默认行为”和“应用级个性化”统一收口到 `ConfigProvider`。本轮新增了一站式配置入口，并保留原有 `ThemeProvider`、`LocaleProvider`、`IconProvider`、`DefaultsProvider` 的独立使用方式，因此不会破坏渐进式接入。

推荐应用侧只创建一次配置：

```ts
import { defineElfUIConfig } from "@elfui/kit";

const config = defineElfUIConfig({
  locale: { locale: "zh-CN" },
  theme: {
    defaultTheme: "brand",
    themes: {
      brand: {
        dark: false,
        tokens: {
          primary: "#2563eb",
          radiusMd: "10px",
          space4: "16px",
          zIndexPopover: 1400
        }
      }
    }
  },
  defaults: {
    Button: { variant: "contained", color: "primary" },
    Input: { variant: "outlined" }
  },
  display: {
    mobileBreakpoint: "md",
    thresholds: { sm: 640, md: 900, lg: 1200 }
  },
  motion: "system"
});
```

```html
<elf-config-provider :config.prop="config">
  <app-root></app-root>
</elf-config-provider>
```

## 对标 Vuetify 的配置面

Vuetify 的 `createVuetify` 将主题、图标、默认值、显示断点、国际化、日期适配器、滚动定位和 SSR 等能力作为相互独立的子系统注入；ElfUI 采用相同的“配置对象 + Provider”思路，但优先实现与当前 Custom Element 架构最匹配的部分。

| 领域 | ElfUI 当前能力 | 建议 |
| --- | --- | --- |
| 组件默认值 | `defaults` 支持全局、组件级、嵌套覆盖、`reset`、`disabled` | 保持 `DefaultsProvider` 作为低层能力，应用入口使用 `ConfigProvider` |
| 主题 | 命名主题、`light/dark/system`、完整 token、主题继承、`data-theme` | 后续补充 token 类型生成和主题编辑器 |
| 样式个性化 | CSS variables、`theme.tokens`、圆角/间距/阴影/动效/z-index token | 统一 token 命名，并提供 CSS 变量清单 |
| 图标 | `IconProvider` 的别名、集合和默认集合 | 后续增加 MDI/Lucide 等可选集合包的适配示例 |
| 语言 | `LocaleProvider` 的 locale、messages、fallback、RTL | 后续增加消息文件拆分和按需加载 |
| 响应式 | `display` 断点、`is/up/down`、SSR 宽度、`data-breakpoint` | 后续增加容器级断点，避免仅依赖 viewport |
| 动效 | `motion: system/full/reduced`，自动响应系统偏好 | 所有组件动画应继续使用统一动效变量 |
| 日期 | 尚未提供可替换 date adapter | 作为 P2 增加 Day.js/Date-fns 适配协议 |
| 滚动定位 | 尚未提供 goTo 服务 | 作为 P2 增加可配置容器、偏移、缓动和持续时间 |
| SSR | 提供 display 的 SSR 初始值 | 后续验证 hydration 和自定义元素服务端输出 |
| 组件注册 | 当前仍通过统一 components 入口注册 | 后续可评估按需注册，但不要牺牲类型和文档体验 |

## 本轮代码收敛

### 已完成

1. 把默认值解析、属性名转换、全局/组件级合并提取到 `Providers/defaults.ts`，`DefaultsProvider` 只负责生命周期、遍历和观察。
2. 把主题 token 统一写入 `ThemeProvider`，支持数字 token（例如 z-index 和 spacing）且正确保留 `0`。
3. 新增 `ConfigProvider`，将默认值、主题、语言、图标、断点和动效偏好组合成一个入口。
4. 统一 overlay 的 z-index token，避免 Dropdown、Popover、Dialog、Toast、Loading 之间依赖散落的魔法数字。
5. 将 AppShell 的 Provider 嵌套收敛为一个配置入口，保留子 Provider 的独立能力。
6. 对 Loading 的派生状态使用 `useComputed`，降低模板表达式复杂度并满足 beta.11 宏编译器的静态分析要求。
7. 新增 ConfigProvider 页面、三组案例、API 说明和定向测试。

### 结构约束

- 状态集中在组件顶部，事件和副作用集中在生命周期区块，模板只消费已命名的派生值。
- 可复用的合并、归一化、CSS 变量映射放在无 DOM 的纯函数文件中，便于单测。
- Provider 只做上下文边界和资源清理，不把业务案例逻辑塞进 Provider。
- 复杂配置使用 `.prop` 传递，字符串属性仅用于简单开关。

## 框架评价与后续建议

### 做得好的地方

- Custom Element 让组件可以脱离具体应用框架使用。
- Shadow DOM 隔离样式，配合 CSS variables 仍然保留主题扩展能力。
- Provider 体系已经覆盖默认值、主题、语言和图标，扩展边界清晰。
- 宏组件静态分析约束有利于最终产物可预测，避免运行时拼接模板带来的不可控成本。

### 仍需增强的地方

1. **配置类型生成**：从组件 metadata 自动生成 `defaults` 的组件名和属性类型，减少字符串配置错误。
2. **token 分层**：区分基础 token、语义 token 和组件 token，并输出主题 token 文档。
3. **Overlay 管理器**：统一 teleport、焦点恢复、Escape、滚动锁定和 z-index，降低各组件重复实现。
4. **可访问性回归**：把 `aria-hidden`/focus、键盘导航、RTL 纳入浏览器级测试矩阵。
5. **日期与滚动协议**：提供可替换 date adapter 和 goTo 服务，覆盖国际化项目的常见需求。
6. **SSR/hydration**：明确 Custom Element 在 SSR 下的占位、升级时机和客户端 hydration 约束。
7. **按需注册**：等组件 metadata 和构建插件稳定后再提供按需注册，避免现在引入两套注册心智模型。
8. **文档自动化**：从 API metadata 生成属性表、事件表和案例目录，减少页面与实现漂移。
