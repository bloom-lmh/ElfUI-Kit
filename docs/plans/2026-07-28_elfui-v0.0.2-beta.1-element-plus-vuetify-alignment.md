# ElfUI v0.0.2-beta.1 Element Plus / Vuetify 对齐收尾计划

日期：2026-07-28

状态：执行中

目标版本：`@elfui/kit 0.0.2-beta.2` 起分批交付

## 1. 目标与原则

本计划用于补齐 ElfUI Kit 作为通用组件库的最后一批能力，不按目录或组件名机械复制 Element Plus、Vuetify。

对齐原则：

1. Element Plus 作为组件 API、交互语义和企业表单能力的主要参照。
2. Vuetify 作为全局配置、主题、布局、国际化、无障碍和构建体验的主要参照。
3. ElfUI 已有等价能力时增强现有组件，不新增同义组件。
4. 每项新增能力必须同时交付类型、测试、案例、API 文档和截图。
5. 所有 Core、Compiler、Vite Plugin 版本必须严格一致；启用 Fragment 前先升级至 `0.1.0-beta.12`。

非目标：

- 不复制第三方源码、DOM 结构或私有样式。
- 不为了目录对齐拆出仅有名称差异的组件。
- 不用全局配置替代组件自身清晰、可预测的 props。
- 不在 API 尚未稳定时承诺永久兼容的深层导入路径。

## 2. 当前能力基线

ElfUI Kit 当前已有约 79 个文档入口、118 个组件 TypeScript 文件、156 个测试文件和 326 个拆分案例，常用组件覆盖已经较高。

已存在、无需重复建设的能力：

- `Popover`、`Tooltip`、`PopConfirm`、`Dialog`、`Drawer` 和通知服务。
- `Table`、`TableV2`、`VirtualList`、虚拟 Tree、虚拟 Transfer。
- `DatePicker`、`TimePicker`、`Calendar`、`ColorPicker`。
- `ConfigProvider`、Theme、Locale、Icon、Display、Motion、Defaults。
- CSS 工具类、Layout、Grid、Flex、Anchor、BackTop。
- 无障碍和 Build & styles 指南页面。

因此后续重点不是继续堆叠基础组件，而是补齐复合能力、统一配置协议、构建入口与生态质量。

## 3. 对齐判断

| 维度 | 当前判断 | 收尾重点 |
| --- | --- | --- |
| 常用组件广度 | 较高 | 补 TreeSelect、DateTimePicker、TimeSelect、MessageBox |
| 表单 API | 较高 | 统一空值、清空值、字段状态、日期适配器 |
| 数据组件 | 较高 | Select 虚拟化、统一大数据契约和性能门禁 |
| 全局配置 | 中高 | 补日期、滚动、别名、外部 i18n 和服务默认值 |
| 主题个性化 | 中高 | 形成稳定 token 契约、品牌 preset 与类型文档 |
| 无障碍 | 中高 | 自动化键盘、焦点、ARIA 和弹层栈验证 |
| 构建与按需使用 | 中 | 稳定单组件入口、resolver、注册清单、体积预算 |
| 国际化与生态 | 中 | 完成英文案例，增加宿主框架集成模板和兼容矩阵 |

## 4. P0：组件与 API 收尾

### 4.1 TreeSelect

以 `Tree` 的数据模型、键盘、虚拟化能力和 `Select` 的触发器、标签、表单契约组合实现，不复制两套树逻辑。

范围：

- 单选、多选、严格勾选、父子联动。
- 可搜索、懒加载、虚拟化、清空、禁用。
- `modelValue`、`valueKey`、字段映射和表单校验。
- 树面板宽度、最大高度、teleport、定位和焦点返回。

案例：

- 基础单选。
- 多选与折叠标签。
- 搜索、懒加载与虚拟树。
- 表单校验、禁用和自定义字段。

验收：

- 共用 Tree/Select 的纯逻辑，不复制选中和键盘算法。
- 键盘可完成展开、移动、选择、关闭并恢复焦点。
- 1 万节点虚拟案例只渲染视口附近节点。

### 4.2 DateTimePicker

组合 `DatePicker` 与 `TimePicker` 的状态和弹层，不复制日期面板。

范围：

- 单值、范围、默认时间、快捷项、禁用日期/时间。
- 日期与时间分阶段确认，支持清空和再次选择。
- 格式化值与提交值分离。

案例：

- 日期时间。
- 日期时间范围。
- 默认时间、禁用时间与快捷项。
- 表单、格式化和时区边界说明。

### 4.3 TimeSelect

提供固定步长时间选择，和自由滚轮式 `TimePicker` 分工明确。

范围：

- 起止时间、步长、最小/最大时间。
- 禁用区间、可清空、格式化和键盘选择。

案例：

- 营业时间。
- 会议时间段。
- 禁用区间与表单校验。

### 4.4 MessageBox

在 `Dialog` 基础上提供 Promise 服务，不再创建第二套模态层实现。

范围：

- alert、confirm、prompt。
- beforeClose、异步确认、输入校验、危险操作。
- 焦点陷阱、焦点恢复、Escape、遮罩和滚动锁。
- ConfigProvider 中的默认按钮文案、位置与 z-index。

案例：

- 确认与取消。
- 异步提交。
- 输入与校验。
- 危险操作和自定义内容。

### 4.5 Select 大数据模式

优先为 `Select` 增加稳定的 `virtual` 能力并复用 `VirtualList`，暂不新增仅名称不同的 `SelectV2`。

范围：

- 固定高度虚拟列表、远程搜索、分组、创建项。
- 高亮项自动滚入视口。
- 选中态与活动态分离。
- 动态过滤后保留合理焦点。

案例：

- 10,000 项单选。
- 10,000 项多选。
- 远程搜索、加载、空态和错误恢复。

验收：

- 首次展开不挂载完整数据。
- 键盘移动不依赖滚动后才刷新。
- 排序、过滤和选择后的活动项一致。

## 5. P0：全局配置补齐

### 5.1 空值与清空协议

在 ConfigProvider 增加类型安全的表单通用配置：

- `emptyValues`
- `valueOnClear`
- 对 Input、Select、Cascader、Picker 生效的组件级覆盖

要求：

- 组件显式 prop 优先于 Provider。
- 不改变已有默认行为。
- `null`、`undefined`、空字符串的提交语义必须有文档和测试。

### 5.2 服务组件默认值

为 Message、Notification、Dialog、MessageBox、Loading 提供受控的默认配置：

- duration、position、offset、zIndex。
- confirm/cancel 文案和危险操作默认值。
- reduced-motion 下的过渡策略。

配置必须按 App/Provider 隔离，不使用进程级可变单例。

### 5.3 Date adapter

定义小而稳定的日期适配协议，使 Picker 不绑定某个日期库。

首版覆盖：

- parse、format、compare、add、startOf。
- 周首日、月份名、星期名。
- 原生 Date 默认实现。

后续可由生态包适配 Temporal、Day.js 或 date-fns，核心包不直接依赖这些库。

### 5.4 goTo 服务

统一 Anchor、BackTop、Tour 和文档目录的滚动行为：

- container、target、offset、duration、easing。
- 横向/纵向滚动。
- reduced-motion 自动降级。
- 中断、替换和完成状态。

2026-07-28 第一阶段：

- [x] 提供公开 `goTo()` / `useGoTo()`，覆盖 selector、Element、数值目标、自定义容器、横纵轴、offset、duration、easing、取消、替换和完成状态。
- [x] ConfigProvider 支持 `goTo` 默认策略并自动遵循 reduced-motion。
- [x] Anchor 与 BackTop 迁移到公共能力，保留各自公开 API 与组件语义。
- [ ] Tour 与 DocsToc 在后续交互回归批次接入；接入前先补滚动中断与焦点特征测试。

### 5.5 外部 i18n 适配

LocaleProvider 保留内置 messages，同时增加外部翻译函数适配接口：

- `t(key, params)`
- fallback locale
- number/date formatter
- RTL 方向

不让组件直接依赖 Vue I18n、i18next 等具体实现。

### 5.6 类型安全 aliases

支持用户给常用组件建立品牌别名并预设 defaults，例如 `PrimaryButton`、`DangerDialog`。

约束：

- 别名在构建/注册阶段确定。
- 生成唯一 Custom Element tag。
- 类型、文档和按需入口可追踪原组件。
- 不支持运行时替换已注册的浏览器 Custom Element。

## 6. P1：Vuetify 式跨组件能力

### 6.1 Overlay 协调服务

现有弹层组件和 Core 组合式函数已经能处理单个交互，但仍需要统一协调：

- [x] 第一阶段：Dialog / Drawer 接入跨组件模态弹层栈。
- [x] 第一阶段：Escape 只关闭最上层，mask 只响应最上层。
- [x] 第一阶段：打开/关闭焦点恢复与 Shadow DOM Tab 圈定。
- [x] 第二阶段：modal 与 anchored overlay 共用交互栈，同一事件只由最上层浮层认领。
- [x] 第二阶段：Dropdown、Tooltip、PopConfirm 接入统一 Escape / outside click 协议。
- [x] 第二阶段：Dialog → PopConfirm 案例与关闭顺序回归。
- [x] 第二阶段：DatePicker、TimePicker、ColorPicker 接入统一 Escape / outside pointer 协议。
- [x] 第二阶段：Dialog → DatePicker 案例与关闭顺序回归。
- [ ] 第二阶段：Select、Cascader 与其余内部 anchored surface 接入统一协议。
- `inert`、`aria-hidden` 与辅助技术安全。
- 多层滚动锁计数。
- teleport 容器和定位刷新。

Dropdown、Select、Cascader、Picker、Tooltip、Dialog、Drawer 必须接入同一协议。

### 6.2 Application layout 协调

Layout 不只提供容器，还应能登记 Header、Footer、Aside、BottomNav 的占位信息：

- fixed/sticky 区域自动计算 main inset。
- 响应式折叠和移动端 overlay。
- RTL、safe-area 和嵌套布局。

只保留少量常用布局组件，复杂模板放入案例，不为每种页面骨架新增组件。

### 6.3 Platform / SSR 初始状态

ConfigProvider 增加可注入的初始平台信息：

- 初始 viewport、breakpoint、touch、reduced-motion、color-scheme。
- 服务端和首屏客户端状态一致。
- 当前 ElfUI 内部 Shadow DOM 仍按 client-only island 处理，文档明确边界。

### 6.4 Theme preset 与 token 契约

将主题从“可覆盖 CSS 变量”提升为稳定的设计系统契约：

- semantic color、surface、state、typography、radius、spacing、elevation、motion。
- token 的 TypeScript 类型与文档自动生成。
- 官方 light/dark 和一个独立品牌 preset。
- 组件只读取语义 token，避免散落硬编码颜色。

## 7. P1：文档、国际化和无障碍

### 7.1 英文完整度

- 所有页面标题、说明、交互状态、空态和案例数据支持中英文。
- 页面脚本统一使用文档翻译 helper，禁止新增硬编码中文交互状态。
- CI 扫描案例中的未声明中文字面量并维护允许列表。

### 7.2 案例规范

每个新增能力至少包含：

- 最小用法。
- 受控状态。
- 禁用、空、加载和错误边界。
- 键盘与焦点。
- 表单或真实业务组合。
- 完整 Script，不隐藏关键状态和方法。

删除仅数据不同、行为相同的重复案例。

### 7.3 无障碍门禁

在现有单元测试之外增加浏览器级检查：

- Tab 顺序、方向键、Home/End、Escape。
- Dialog/Drawer 焦点陷阱和恢复。
- 菜单、树、Tabs、Grid 的 ARIA role/state。
- 高对比度、200% 缩放、RTL、reduced-motion。
- 弹层关闭时不得把焦点留在 `aria-hidden` 子树。

## 8. P1：构建与生态

### 8.1 稳定单组件入口

设计公开且可长期维护的入口：

```ts
import { Button } from "@elfui/kit/button";
import "@elfui/kit/button/style.css";
```

要求：

- 生成 exports map、类型和注册清单。
- 单组件入口不隐式注册全库。
- 保留全量入口。
- 明确组件样式和 utilities 的副作用边界。

### 8.2 Resolver 与自动导入

提供官方 resolver：

- 根据标签解析组件入口和样式。
- 支持自定义 `tagPrefix`。
- 能读取别名与注册清单。
- 在 Vite 环境中验证真实 tree-shaking 结果。

### 8.3 宿主框架模板

为 Native、React、Vue、Svelte、Angular 各保留一个最小集成项目，验证：

- property、attribute、CustomEvent。
- slot、CSS custom property、`::part()`。
- focus、form-associated、自定义方法。
- 卸载和重复挂载资源清理。

## 9. 明确不拆出的重复组件

除非真实用户 API 出现无法兼容的冲突，否则：

- 不新增独立 VirtualTable，继续由 `TableV2`/Table 大数据能力承载。
- 不新增独立 VirtualTree，继续增强 Tree。
- 不新增 SelectV2，优先给 Select 增加 virtual 模式。
- 不把日期、颜色内部面板直接公开成组件。
- 不为每种 Layout 页面骨架新增一个组件。
- 不重复建设 Popover、虚拟列表或滚动条组件。

## 11. 单项完成定义

每项任务只有同时满足以下条件才可标记完成：

1. API、类型和默认行为已确定。
2. 状态、纯逻辑、DOM 副作用和模板边界清晰。
3. 组件测试、纯逻辑测试和浏览器交互测试通过。
4. 至少一个中英文页面和必要案例完成。
5. Playground 展示完整 Template 与 Script。
6. light/dark、RTL、键盘、缩放和窄屏验证通过。
7. 新增或变化的 UI 有截图证据。
8. 全量 typecheck、test、build 通过。
9. 公开 API 和包体积变化已记录。
