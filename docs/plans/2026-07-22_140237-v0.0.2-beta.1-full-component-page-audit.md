# ElfUI Kit 全组件、全页面审计与修复计划

- 日期时间：2026-07-22 14:02:37（Asia/Shanghai）
- 版本：0.0.2-beta.1
- 范围：全部公开组件路由、全部组件文档页面、全部 Playground、全部本页目录，以及组件分类导航
- 原则：保留页面 H1；示例标题进入 Playground；API 目录统一；交互示例提供足够的 Template 与 Script；不覆盖其他线程的无关改动

## 目标

1. 逐页验证本页目录的每一个项目能定位到真实章节，并修复失效、重复、错误激活和 Shadow DOM 跨层定位问题。
2. 逐个 Playground 审计源码完整度。凡示例包含状态、事件、异步、命令式方法、动态数据或 Provider 配置，必须提供可复制的 Script；纯声明式示例可以保留禁用的 Script 标签，但 Template 必须完整。
3. 对全部组件页面建立案例能力矩阵，记录现有案例、重复案例、必须补充案例和优先级；本轮直接补齐可从现有页面行为准确推导的 Script 缺口。
4. 审计组件分类、路由命名和导航层级，给出保留、移动、合并或增加分组的建议，不在缺少产品决策时擅自大规模迁移公开路径。

## 执行步骤

### A. 全量清单与自动审计

- 从 `src/routes/index.ts` 提取全部公开路由和菜单分组。
- 从 `src/pages` 提取页面、Playground、Template/Script、H1/H2/API 和页面测试覆盖。
- 输出机器可复查的页面审计数据，排除 Home 与内部 Debug 页面。

### B. 目录跳转修复

- 为 DocsToc 增加稳定的目标解析、唯一 ID、API 合并和可滚动容器定位回归测试。
- 用真实浏览器逐路由点击每个目录项，验证目标元素、滚动位移与激活状态。
- 修复没有目标、目标重复、点击不移动、目录显示但章节被隐藏等问题。

### C. 示例 Script 补齐

- 将示例分为：声明式、受控状态、事件、异步、命令式、Provider/服务调用六类。
- 自动发现有事件/动态绑定但无 Script 的 Playground，并逐一核对页面实现。
- Script 使用与真实示例一致的变量和方法，保证复制后可以理解，不写空泛占位说明。

### D. 案例与分类报告

- 按 Basic、Layout、Form、Feedback、Data、Navigation、Picker、Providers、Utilities 汇总。
- 每个组件记录：现有案例数、Script 覆盖、测试覆盖、必须补充案例、可合并案例、优先级。
- 给出分类调整建议及兼容迁移策略。

### E. 验证

- 运行 DocsToc、Playground 和被修改页面的定向测试。
- 运行全量测试、宏类型检查和生产构建。
- 保存代表性浏览器截图，并在最终报告中记录未能自动验证的例外。

## 完成标准

- 公开组件页面 100% 纳入清单。
- 所有可见目录项均有唯一目标并可跳转。
- 所有需要逻辑说明的示例均有 Script，且 Script 与页面真实实现一致。
- 输出完整案例缺口与分类建议报告。
- 定向测试、类型检查和生产构建通过；全量测试失败时明确区分既有失败与本轮失败。
