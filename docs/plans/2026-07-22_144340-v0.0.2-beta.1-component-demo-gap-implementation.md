- 目标：将审计报告中的新增案例转化为可运行的组件能力、文档示例、组件测试和真实浏览器截图证据。

## 质量门槛

1. 案例不得伪造组件尚未支持的行为；缺能力时先补组件契约，再写案例。
2. 示例状态集中声明、派生状态相邻、方法集中声明；`Template` 与 `Script` 必须可以指导真实接入。
3. 交互边界至少覆盖键盘、焦点、禁用、加载、空、错误、清理或销毁中的适用项。
4. 每完成一个组件，执行定向组件测试和页面集成测试；每完成一批，执行构建和真实浏览器截图验收。
5. 截图统一保存在 `docs/screenshots/2026-07-22-component-demo-gaps/`，实施结果回写审计报告。
