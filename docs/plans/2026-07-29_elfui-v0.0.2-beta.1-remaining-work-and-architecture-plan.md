## 1. 总目标

后续工作同时推进四条主线：

1. 对齐 Vuetify 的跨组件能力、全局配置和设计系统边界。
2. 对齐 Element Plus 的组件公开 API、交互语义和常用组件广度。
3. 按能力协议优化 ElfUI Kit 的代码结构和封装，保持高内聚、低耦合、可测试和良好性能。
4. 全面完成组件页面、案例、运行时状态和 API 表的英文适配。

所有重构默认满足以下约束：

- 不改变现有组件视觉样式、布局、DOM 语义和公开行为。
- 不以减少行数作为目标，不进行无关格式化或批量样式重写。
- 不新增 `fragment` 或 `defineFragment()`，并迁移现有用法。
- 不通过组件侧补丁掩盖 ElfUI 框架问题。
- 不复制 Element Plus 或 Vuetify 的内部实现。
- 不为了抽象而建立万能 composable、万能基类或跨组件共享 DOM 外壳。

## 3. Fragment 禁用与迁移

### 3.1 强制规则

- 新代码不得 import、调用或重新导出 `fragment`、`defineFragment`。
- 不使用匿名 Fragment、命名 Fragment 或 `array.map(fragment)`。
- `v-for` 列表必须提供稳定 key。
- 模板必须是直接传给 `defineHtml()` 的静态可分析模板字面量。
- 不用运行时字符串、模板变量或自制 HTML 拼接替代 Fragment。

### 3.2 Dropdown 迁移

现有三个 Fragment：

- `StandardTrigger`
- `SplitTrigger`
- `MenuPanel`

迁移要求：

1. 保留现有 DOM 顺序、class、part、ARIA、事件和 CSS 选择器。
2. 优先将纯结构内联回根模板，并继续消费已命名派生值和方法。
3. 只有某一区域确实需要跨文件复用、独立生命周期、slot、Shadow Root 或公开 API 时，才建立真实内部 `defineHtml()` 组件。
4. 不为了替换 Fragment 而增加多余 Custom Element 层级。
5. 使用现有截图做像素和交互回归，确保样式无变化。

### 3.3 防回归

- [x] 新增静态扫描，发现 `fragment` / `defineFragment` 即失败。
- [x] 已更新 ElfUI Kit authoring skill、宏规则、代码结构和 beta.18 参考，删除 Fragment 推荐并改为显式禁用。
- [x] 框架升级时继续由 `check-unsupported-macros.mjs` 保留门禁，不因 Core 暂时仍导出 API 而恢复使用。

## 4. 架构原则

### 4.1 依赖方向

```text
公开类型与能力协议
  -> 纯函数 / 无界面 service
    -> Provider / composable adapter
      -> 内部交互基元
        -> 公开组件
          -> 页面、案例、Props 表和契约测试
```

公开组件不得依赖另一个公开组件的私有实现。组合组件只能依赖稳定协议、公开类型或明确的内部基础能力。

### 4.2 责任边界

- 纯函数：规范化、索引、过滤、排序、范围、几何、格式化和状态转换。
- Service：跨组件且无渲染依赖的能力，必须定义取消、完成、错误和清理语义。
- Composable：把 service 绑定到生命周期、Provider 或当前 host，不拥有组件业务状态机。
- Controller：overlay、drag transaction、scroll task、focus scope 等有明确状态转换的协调器。
- Provider：注入默认策略和应用级配置，不保存不必要的进程级可变业务状态。
- 内部组件：只承接真实共享的 DOM、交互、生命周期和无障碍语义。
- 公开组件：拥有自身业务状态机、公开契约和 Shadow DOM。

### 4.3 设计模式

- Strategy：日期运算、滚动 easing、排序、过滤、字段解析和图标解析。
- Adapter：ConfigProvider、外部 i18n、日期库、宿主框架和 Light DOM composition。
- Controller：overlay、focus、滚动、拖拽和异步任务。
- State machine：Cascader 异步路径、Picker 范围选择、Upload 生命周期和 MessageBox 关闭流程。
- Registry：仅用于必须跨实例协调的 overlay stack、metadata 和每容器活动滚动任务。
- Facade：ConfigProvider 只组合子系统，不吞并 Theme、Locale、Icon、Defaults 的独立职责。

### 4.4 抽象准入

满足以下至少一项才抽离：

- 是独立可测试的纯算法。
- 被三个以上语义一致的调用点复用。
- 是一个独立有价值的跨组件能力，且协议、取消和清理语义明确。
- 当前文件同时承担数据模型、DOM 副作用和复杂业务状态机，抽离后能形成清晰责任边界。

相似语法不代表相同语义。不得仅为了减少重复行数建立抽象。

## 5. 不改变样式的重构协议

每个目标组件在修改前建立以下基线：

- light / dark。
- 桌面 / 窄屏。
- 默认、hover、focus、active、disabled、loading、empty、error。
- RTL 和 200% 缩放，适用于有方向或密集布局的组件。
- overlay 打开、嵌套、碰撞翻转和关闭后的焦点。
- 对外 CSS custom properties、`::part()` 和 host 状态属性。

重构约束：

- 不改现有 class、part、CSS 变量和 DOM 层级，除非有明确缺陷和单独批准。
- 不在架构重构中同时调整颜色、间距、圆角、阴影、字号或动画。
- 不进行全文件样式格式化。
- 共享样式优先通过语义 token、mixin 和状态映射实现。
- Shadow DOM 样式继续由组件拥有，不使用全局选择器穿透。

视觉变化如确实必要，必须从架构重构中拆成独立任务并单独说明。

## 6. 性能协议

### 6.1 基线

在继续处理大型组件前记录：

- 首次渲染时间和 DOM 节点数。
- 更新、选择、排序、过滤和键盘移动时间。
- 滚动长任务、掉帧和事件数量。
- 数据替换、关闭和卸载后的监听器、Observer、定时器和对象 URL 清理。
- overlay 打开期间的全局监听器数量和重复注册情况。

使用固定数据、固定浏览器版本和至少 5 次运行的中位数。超过基线 10% 的回退必须解释并修复，不能以单次波动判断。

### 6.2 重点场景

- Table：10,000 行，保持窗口 DOM 有界，不破坏现有快速选择和滚动路径。
- TableV2：固定与动态行高、fixed data、横纵滚动和展开行。
- Tree / TreeSelect：10,000 节点，展开、选择、过滤和虚拟窗口。
- Select：10,000 项单选、多选、过滤和活动项滚入视口。
- VirtualList / Transfer：固定和动态窗口、键盘可见性和数据替换。
- Cascader：深层树、异步竞态、多选传播和 tree/columns 视图切换。
- Upload：并发、分片、取消、失败恢复和卸载清理。
- Overlay：嵌套栈、事件认领、定位刷新和焦点恢复。

### 6.3 热路径规则

- 不在模板中重复过滤、排序、路径查找或构建完整映射。
- 规范化只做一次，使用不可变 snapshot 或 shallow state 避免大数据深代理。
- 高频 scroll/pointer 更新必须合并，不能制造事件风暴。
- 组件卸载必须释放事件、Observer、计时器、任务、Teleport 节点和对象 URL。
- 不为同步正确性增加无依据的 `setTimeout`、轮询或微任务补丁。

## 7. Element Plus 对齐

### 7.1 对齐范围

逐组件维护以下矩阵：

- Props：名称、类型、默认值、attribute/property 转换和兼容别名。
- Events：触发条件、detail 结构、bubbles/composed/cancelable。
- Model：受控/非受控、更新事件、清空、reset 和 modifiers。
- Slots：默认、命名、fallback 和重复项作用域。
- Exposes：只保留语义化命令，避免覆盖 HTMLElement 原生方法。
- 行为：键盘、焦点、disabled、readonly、loading、empty、错误恢复和异步竞态。
- Forms：name、required、disabled fieldset、校验、reset、restore 和 FormData。
- Accessibility：原生语义、ARIA、roving tabindex、active descendant 和 live region。

### 7.2 对齐策略

- API 兼容输入在边界处统一规范化，内部只消费标准形态。
- Vue 专属能力必须翻译为 Web Components 契约，不机械复制。
- 对不适合 Custom Elements 的 API，记录等价能力和边界，不伪造空实现。
- 新增 alias 时必须说明优先级、弃用策略和类型。
- 组件当前已完整满足高频契约时，不为“名称数量相等”继续扩张 API。

- `inert` / `aria-hidden` 与辅助技术安全。
- scroll lock 计数。
- teleport 容器、visual viewport、fixed 定位和刷新。

组件保留自己的内容、选择状态和定位选项，不共享一套万能 DOM。

### 9.2 Field 与 Form

统一协议包含：

- size、variant、disabled、readonly、invalid、loading。
- label、placeholder、prefix、suffix、clear。
- empty value、clear value 和 reset。
- FormItem 状态、校验触发和原生 form callback。
- CSS variables、parts 和 host flags。

组件显式 prop 优先于 Provider，Provider 优先于现有默认值。首轮不得改变默认提交语义。

### 9.3 Collection

统一概念：

- item identity。
- active、selected、expanded、checked、disabled。
- roving tabindex / active descendant。
- Home、End、方向键和 typeahead。

Select、Menu、Tabs、Tree、Transfer 保留各自 role 和选择语义。共享层只提供无 UI 的小协议和纯算法。

### 9.4 Virtual window

继续以 `src/utils/virtual-window.ts` 为唯一窗口算法：

- fixed size。
- cumulative variable offsets。
- overscan。
- scroll-to-index。
- 数据变化后的锚点恢复。

组件只拥有测量、渲染、键盘和业务状态。

### 9.5 Date

先定义小型 adapter：

- parse、format、compare、add、startOf。
- startOfWeek、month names、weekday names。
- locale 和 time zone 输入。

原生 Date 为默认实现。Temporal、Day.js、date-fns 通过 adapter 扩展，核心包不直接依赖日期库。

## 13. 框架问题处理协议

发现疑似 ElfUI Core、Compiler、Vite Plugin 或 Router 问题时：

1. 停止在组件中增加补丁。
2. 建立最小复现，隔离组件库业务代码。
3. 记录期望行为、实际行为、版本、浏览器、触发步骤和影响组件。
4. 告知维护者，等待框架结论。
5. 继续推进不依赖该问题的任务。

禁止的组件侧规避：

- 任意延时、轮询或多次 nextTick 等待框架状态。
- 手写 Provider/Teleport 全局桥。
- 捕获并吞掉 DevTools 或编译器错误。
- 为 scoped slot 伪造空 API。
- 复制框架已有但暂时异常的生命周期、焦点或表单实现。

当前需要跟踪：

- [x] beta.18 已解决 `useComputed` 同事务写后立即读旧缓存问题；保留最小回归测试，不在组件侧调用 `flushSync()`、微任务或延时规避。
