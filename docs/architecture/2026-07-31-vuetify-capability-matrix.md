# Vuetify Capability Matrix

- Authority version: `vuetify@4.1.7`
- Authority source: [Vuetify v4.1.7](https://github.com/vuetifyjs/vuetify/tree/v4.1.7)
- Kit version: `@elfui/kit@0.0.2-beta.1`
- Core version: `@elfui/core@0.1.0-beta.20`
- Scope: cross-component ownership and alignment only; this matrix does not claim
  component-level parity or browser acceptance.

This matrix is the first lookup for Vuetify alignment work. The official source is
the authority for Vuetify behavior; the Kit source is the authority for the current
ElfUI contract. A follow-up package owns every gap. Components must consume the
listed owner instead of creating a local copy of the capability.

## Status Vocabulary

| Status           | Meaning                                                                                                       |
| ---------------- | ------------------------------------------------------------------------------------------------------------- |
| `supported`      | The Kit exposes the same capability boundary with no recorded alignment work.                                 |
| `equivalent`     | The Kit exposes a valid Web Components equivalent, but names, installation, or framework-only details differ. |
| `missing`        | The Kit has no single public owner for the capability required by the Vuetify contract.                       |
| `not applicable` | Vuetify does not provide a corresponding cross-component capability; Kit behavior remains Kit-owned.          |

## Boundary Decisions

- Vuetify's plugin-only `components`, `directives`, `aliases`, `blueprint`, and `ssr`
  options are recorded as installation/configuration authorities, not copied as
  Vue-specific APIs into Custom Elements.
- Kit's 11 directive capabilities include the eight Vuetify names plus Draggable,
  Loading, and Infinite Scroll. The extra capabilities are Kit-owned and are not a
  parity defect.
- Vuetify has no equivalent cross-component service registry. Kit services therefore
  remain a separate facade/controller capability; only the documented Core scroll-lock
  migration is an alignment follow-up.
- This document records ownership and gaps. It does not close `VU-02`, `VU-03`,
  `VU-04`, `VU-05`, `OP-03`, `OP-05`, or `OP-07`.
